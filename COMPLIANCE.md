# Compliance Matrix

This document maps superCPE behavior to the 2026 Statement on Standards for
CPE Programs (`docs/2026-Statement-on-Standards-for-CPE-Programs.pdf`) and
nothing else. Each row ties a Standards locator to the feature that satisfies
it, the code that implements it, and any known gap. Rows are added as features
ship; an empty table means no Standards-touching feature has shipped yet.

| Locator | Requirement | Feature | Where in code | Gap |
|---------|-------------|---------|---------------|-----|
| 3.01.1 | "Learning activities provided by CPE program sponsors must specify the knowledge level, content, and learning objectives … Knowledge levels consist of Basic, Intermediate, Advanced, Update, and Overview." | 002 | `backend/app/constants/knowledge_levels.py`; validation rule 9 in `backend/app/services/packages.py`; CHECK constraint in `backend/app/models/lesson_package.py` | Ingest enforces the five levels on stored lessons. Communicating level, content, and objectives to potential participants needs a participant-facing surface that does not exist yet. |
| 3.02.1 | "All programs identified as Intermediate, Advanced or Update must clearly identify prerequisite education, experience, and advance preparation in precise language … For courses with a program knowledge level of Basic and Overview, prerequisite education or experience and advance preparation, should be noted if applicable, otherwise, state 'none' in the course announcement or descriptive materials." | 002 | Validation rule 10 in `backend/app/services/packages.py`; `LEVELS_REQUIRING_PREREQUISITES` and `PREREQUISITES_NONE` in `backend/app/constants/knowledge_levels.py` | superCPE refuses blank prerequisites/advance preparation for Intermediate, Advanced, Update and stores the literal "None" for blank Basic/Overview. It cannot judge whether stated prerequisites are "precise language"; that is the content reviewer's call (feature 008). No course announcement exists yet to display them in. |
| 7.02.7 | "If the entire self study program constitutes a video, then the prescribed word count formula … would consist of the actual video time plus the total number of review questions … multiplied by 1.85, divided by 50" — the duration term must be "the actual audio/video duration time (not narration of the text)". | 002 | `backend/app/services/ffprobe.py`; validation rules 4–5 in `backend/app/services/packages.py`; `duration_source = 'measured'` CHECK in `backend/app/models/lesson_package.py`; boot check in `backend/app/main.py` | The duration is measured by ffprobe on the server against the file that was uploaded, and a manifest claiming anything but `measured` is refused. superCPE cannot verify video-tool's claim that the narration inside the file was rendered from measured audio; it relies on that attestation and refuses packages that do not make it. Credit computation from this duration is a later feature. |
| 9.02.1(8), 9.02.2(7) | "Program materials." — among the required documentation elements CPE program sponsors must retain as evidence of compliance (9.01: for a minimum of five years). | 002 | `lesson_packages` stores the manifest, questions, and transcript verbatim (`backend/app/models/lesson_package.py`); the video is retained at `video_key` via `backend/app/storage.py` | Retention is currently a local disk under `backend/uploads/`; five-year durability (DigitalOcean Spaces, backups) is not implemented yet. Nothing is ever deleted, but nothing enforces the retention period either. |
| 9.01 items 1, 8, 9, 10, 11 | Certificates of completion must include "1) CPE program sponsor name … 8) NASBA sponsor identification number 9) State registration number, if required by the state boards 10) NASBA time statement stating that CPE credits have been granted on a 50-minute hour 11) Any other statements required by boards of accountancy". | 003 | `sponsor_profile` and `sponsor_state_registrations` in `backend/app/models/sponsor.py`; `TIME_STATEMENT` and `CERTIFICATE_SPONSOR_FIELDS` in `backend/app/constants/certificate.py`; `missing_fields()` gates issuance; admin editing via `backend/app/routers/admin_sponsor.py` | superCPE is not on the National Registry, so item 8 cannot be satisfied today: `registry_status` is `not_registered`, and the rule is that while it is, `national_registry_id` must be empty (CHECK constraint plus validation) and no response, page, or document may include the words "National Registry" or a sponsor ID. This feature enforces that on its own responses only (`SponsorProfilePublic` drops the field); every later feature that renders sponsor facts must read `may_claim_registry`. No certificate is rendered yet (feature 010). |
| 9.01.1 | "The entity whose name appears on the certificate of completion is responsible for awarding the CPE credits earned by a participant." | 003 | `legal_name` on `sponsor_profile` (`backend/app/models/sponsor.py`) records the responsible entity; it may equal `name` | Nothing renders a certificate yet, so no name "appears" anywhere; feature 010 must print the entity this row records. |
| 9.02 | "CPE program sponsors must retain adequate documentation (electronic or paper) for a minimum of five years to support their compliance with these Standards and the reports that may be required of participants." | 003 | Nothing is ever deleted (packages from 002, the sponsor profile here), which satisfies the floor by default | The five-year period is not yet recorded anywhere in code; feature 011 adds the constant alongside the audit bundle. |
